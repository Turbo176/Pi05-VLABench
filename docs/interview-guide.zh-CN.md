# 📝 简历表述与面试说明

这份说明对应仓库已经运行并保存证据的版本：一个水果/插花共享 SFT checkpoint，水果任务完成 SFT→闭环评测→PPO→配对评测。三任务全部学会、PPO 总体提升、动作抖动修复仍未完成。

## 简历可用表述

**Pi05-VLABench｜基于 π0.5 的机器人模仿学习与 PPO 后训练**

- 基于 VLABench、MuJoCo、LeRobot 和 RLinf/OpenPI 搭建专家采集、动作回放、数据转换、共享策略 SFT 与闭环评测流程；使用 64 条水果/插花轨迹、9,904 帧训练数据，完成 π0.5 动作专家 LoRA 及动作头微调。
- 对齐相机、语言、归一化、位姿动作与动作块执行方式，验证 SFT checkpoint 零更新加载到 RL 后的预测、动作解码和闭环行为；通过梯度及权重对比确认 PPO 更新了 224 个策略参数张量。
- 在 10 个固定留出场景上完成参考模型/SFT/PPO 配对评测，成功数为 4/10、5/10、5/10；实现置信区间、逐场景结果、同场景换目标测试与可复核实验记录。

## 三分钟讲述顺序

**任务。** 我做的是让一个视觉语言动作模型读取多视角图像和语言指令，在官方仿真里独立完成取放。先用水果和插花示范训练共享模型，再选水果完成 PPO 后训练与对照评测。

**数据。** 示范来自官方专家。保存动作后，我在新的仿真里重新执行动作，并检查官方成功条件；随后转换为 LeRobot，检查图像、状态、动作和时间对齐。当前 SFT 是 64 条完整训练 episode，另有五条验证 episode，和首页三段专家视频不是同一个数量概念。

**训练和部署。** 复用上游 π0.5 与 RLinf 模型，训练动作专家 LoRA 和动作头，冻结视觉语言骨干。比较 SFT 与 RL 零更新状态时的相机、指令、归一化、动作解码和采样，避免把部署接口变化误当成 PPO 的效果。

**结果。** 在十个固定留出起点，参考模型成功四次，SFT 和 PPO 各五次。PPO 恢复了两个 SFT 失败场景，也丢掉了两个 SFT 成功场景，所以总体没有提升；语言测试还有退化。目前能证明的是全流程运行和真实策略更新，性能还需要扩大样本和受控实验。

**排查。** 我把训练损失、末端目标与实际运动分开检查。成功视频里，抓取转抬起时目标有一次约 5.1 厘米跳变，这条 SFT 轨迹的 IK 都成功了。因此还需要检查动作预测和解码，不能直接归因给 IK，更不能只把视频变顺滑。

## 面试追问与证据

| 常见追问 | 回答重点 | 打开哪里 |
| --- | --- | --- |
| 你具体做了什么？ | 数据与回放、LeRobot 对齐、共享 SFT、SFT→RL 接口核验、PPO 接入、固定评测。模型、任务和控制器来自上游。 | [实现分工](system-design.md#what-this-repository-adds) |
| 闭环是什么意思？ | 模型根据当前观测预测动作，执行五个控制步，再读取新图像继续预测，直到成功或预算耗尽。保存动作能回放不等于模型能闭环完成。 | [控制接口](system-design.md#policy-and-control-contract) |
| 都用成功示范，为什么还需要微调？ | 专家成功只是监督标签可靠；模型仍需从图像和指令学会动作映射。评估对象是独立执行的模型，不能把专家成功率当成模型成绩。 | [数据与分割](system-design.md#data-card) |
| 一共多少数据？ | 当前共享模型 47 条水果、17 条插花，共 9,904 帧；验证五条、744 帧。水果含两条专家纠正轨迹。旧三任务 60 条数据是另一版接口，不能混加。 | [数据分布图](experiments/2026-11-23/project-overview/dataset-coverage.png) |
| 为什么不是训练整个模型？ | 这次选择 rank-16 动作专家 LoRA 和动作头，保持视觉语言骨干冻结。当前证据是这个训练范围的结果，没有完成全参数与 LoRA 的公平比较。 | [训练设置](system-design.md#model-and-optimizer-card) |
| SFT loss 降了吗？ | 90 次随机 minibatch loss 波动，没有持续下降趋势；最后一点更低不能代表收敛。固定验证动作误差也没有改善，因此主要看闭环成绩。 | [全部训练曲线](experiments/2026-11-23/training-and-motion/README.md#sft-training) |
| 怎么证明 PPO 真的训练了 VLA？ | 非零策略梯度；216 个动作专家 LoRA 张量、八个动作头张量发生变化；另有八个 critic 张量。保存的优化器状态也达到 19 步。 | [保存权重对比](experiments/2026-11-22/fruit-completion-v1/saved-checkpoint-update-audit.json) |
| SFT→RL 会不会只是换了部署实现？ | 三个真实观测窗口的归一化预测和共享解码误差为零；训练前还复现了一个相同的闭环成功起点。这个检查通过后才更新策略。 | [零更新交接](experiments/2026-11-22/fruit-completion-v1/handoff.json) |
| PPO 用什么奖励？ | 当前是官方成功 + 距离进展；不是拿起 0.5、放入 0.5。分阶段奖励是下一轮候选，还没验证。 | [奖励与论文](fruit-reward-review.md) |
| 为什么 PPO 没提升？ | 只有两条 rollout、731 个控制步和一次迭代；奖励、探索和遗忘都是待检验因素。当前不能确定唯一原因。下一轮从同一 SFT 只改变奖励，并用新测试起点。 | [真实 PPO 记录](experiments/2026-11-22/fruit-completion-v1/ppo/iteration-1.json) |
| 怎么证明模型用到了语言？ | 同场景换目标和换说法，保持初始物理状态、图像不变。动作变了不代表目标做对；当前测试未证明稳健语言跟随。 | [语言测试](experiments/2026-11-22/fruit-completion-v1/README.md) |
| 50% 能说明比 40% 更好吗？ | 这个样本多成功一次，但样本小、区间宽，不能认定可靠提升。报告每个起点的得失，不能只挑成功视频。 | [逐场景图](experiments/2026-11-23/project-overview/paired-results.png) |
| 为什么动作抖？ | 已测到目标跳变和实际运动不连续；它发生在动作块内部，这条轨迹 IK 无失败。采样、预测与解码需要进一步对照，尚未完成修复。 | [动作分析](experiments/2026-11-23/training-and-motion/README.md#motion-in-the-recorded-pear-scene) |
| 能不能现场复现？ | 无 GPU 可核验导出证据和复算分数；官方专家回放需准备仿真环境；模型闭环需额外权重、数据与 GPU。三种复现范围分开说明。 | [运行入口](../README.md#quickstart) |

## 可直接演示的五分钟版本

1. 展示同一梨子场景的 SFT/PPO 视频，说明这只是一个案例，再打开十个起点的逐场景图。
2. 在仓库根目录运行 `python scripts/review_fruit_experiment.py`，现场复算成功数并核对证据文件。
3. 打开 `check_reference_rl_handoff.py`，解释为什么必须先验证零更新加载一致。
4. 打开 PPO 权重变化记录，指出 actor 与 critic 的区别，再展示损失曲线和动作跳变。
5. 用一个具体实验回答下一步：从同一 SFT 做奖励对照，固定交互预算与动作接口，另外注册新留出起点。

这些材料能支持“小规模 VLA 训练与评测工程项目”的说明。若岗位要求稳定多任务泛化、PPO 可复现提升或真实机器人部署，目前仍缺对应实验，单靠调整首页不能补上。
